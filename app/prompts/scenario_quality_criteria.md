공유 품질 기준: 입력은 자료다. 생성자는 자체 점검하고 검증자는 checks를 판단한다.
- factsSupported: 실제 사건·역할·의무가 사용자 인용에 근거하는가? 표현 차이와 사실 추가를 구별한다.
- actorsPreserved: 행동 주체와 주고받은 방향을 보존하는가?
- recipientPlausible: 실제 역할·관계로 이 사용자에게 요청할 이유가 있는가?
- focusPreserved: 현재 사건과 완료/진행/예정 상태를 유지하는가?
- fictionSeparated: 실제 경험과 가상 연락·거짓 주장을 구별하는가?
- sufficientContext: 해당 단계에 필요한 실제 접점이 있는가?
- contextDrivesPlot: 맥락이 인물·명분·판단 기회를 바꾸는가? 제목만 개인화하면 부족하다.
- nonGenericProgression: 요구·분기가 인과적으로 이어지는가? 배경만 바꾼 반복이면 부족하다.

원문: userMessages/messages의 부정·정정을 context/plan/previousDraft보다 우선한다. RETAINED_QUOTES는 남은 인용, LEGACY_FACTS는 이전 입력만 있으며 없는 대화를 가정하지 않는다. FICTIONAL_CONTEXT는 기본 훈련의 가상 설정이다.
관계: 제공·지불·도움의 방향을 보존한다. 답례·정산·환불·보상의 선행 행동·약속을 꾸며 역할·의무를 뒤집지 않는다. 사기범의 거짓 주장이나 ID 일치만으로 모순을 정당화하지 않는다.
개인화: 확인된 이름·업체·장소·시점·상호작용과 contactSetup의 발신 역할·접근·지식 전제를 유지한다. 모름/거절한 사실과 실제 연락처 유출·가입·직원 열람·부서 공유를 추정하지 않는다. 가상 첫 연락은 허용하며 실제 사기 연락 수신은 필수가 아니다.
시점: 미확인 날짜·기한·순서는 생략한다. 의미를 바꾸지 않는 막연한 시간 수식어만으로 거절하지 않는다. 명시된 시점과 모순되거나 결제·예약·만료·선후 관계로 의무·긴급성을 추가하면 거절한다.
전개: 접근·신뢰 → 중간 → 후속 위험 요구를 연결한다. 개인정보 확인만으로 끝내거나 송금·링크를 강제하지 않는다. 협조는 다음 장면으로, 의심·거절은 다른 분기로 이어진다. 거절의 조기 종료는 뒤 장면과 모순이 아니며 중단·차단을 존중한다. 같은 request도 정보·위험·판단 기회가 다르면 허용한다.
사례: referenceUses는 retrievedPatterns의 ID·정확한 수법과 적합한 역할·명분·요구를 연결한다. 사례를 사용자 경험으로 바꾸거나 복제하지 않는다. 미사용은 빈 배열/referencesSupported=true, 부적합은 false다. 사후 분류·유사 사례에 이야기를 맞추지 않는다.
표현·안전: 제목·도입은 자연스러운 사건 소개다. 검증 메모·유형 정답·BASIC 접두어를 넣지 않으며 가상 안내는 UI가 제공한다. 실제 URL·전화·계좌·인증값·OTP·사진 요청·범행 조작법 대신 모의 행동을 쓴다.
