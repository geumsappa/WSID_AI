# 대화와 상세 생성을 분리한 시나리오 흐름

## 대화 단계

`/internal/ai/discovery/next`는 `discovery_brief` 모델 호출 한 번만 수행한다.
짧은 다음 질문 또는 맥락이 준비되었다는 판단과 인용 근거만 반환한다. 활동 이름만으로 준비 완료하지 않는다.
이 단계는 사실 그래프·사기 유형·전체 계획을 만들거나 별도 의미 검증 모델을 호출하지 않는다.

마스킹된 사용자 발언을 `facts.discoveryEvidence`에 보관한다. 질문은 사용자 사실에 포함하지 않는다.
최대 20개 발언, 직렬화 9000자 이내의 최근 기록을 유지한다. 컨텍스트가 잘린 요청에서도 저장된 근거와 현재 입력을 합친다.
새 답변은 이전 계획/준비 상태를 그대로 재사용하지 않는다. 준비 판정의 quote는 실제 사용자 발언과 대조한다.
`canGenerateScenario=true`는 상세 생성을 시도할 맥락이 있다는 뜻이며, 상세 검증 통과를 보장하지 않는다.

## 시나리오 만들기 단계

사용자가 생성을 요청하면 다음 순서로 처리한다.

1. 저장된 사용자 근거로 사실 그래프와 계획을 한 번에 추출한다.
2. 인용 출처, 행동 주체, 사건 ID, 개인화 근거와 참조 자료를 코드로 검사한다.
3. 별도 모델 호출로 사실·주체 보존, 수신 이유, 맥락 충분성, 실제/가상 구분을 검토한다.
4. 통과한 계획으로 본문을 생성한다.
5. 본문의 구조·안전성 및 의미를 다시 검사한 뒤 반환한다.

빠른 대화 판단이 잘못됐어도 상세 검증을 생략하지 않는다. 상황이 부족하면 422로 추가 설명을 요청하며 생성기는 호출하지 않는다.
생성의 제한된 재시도는 유지하고, 계속 실패하면 명시적 오류를 반환한다. 무관한 기본 시나리오로 성공을 가장하지 않는다.
이전의 그래프/계획 기반 상태와 facts-only 요청 경로도 유지한다. 기존 상세 context-turn API의 검증 흐름은 변경하지 않았다.

## 충분한 맥락의 기준

활동·품목·장소 이름만으로 일반적인 이야기를 떠올릴 수 있다는 것은 충분하지 않다.
관계자의 실제 역할/행동, 진행 방식, 구체적인 상호작용 같은 근거 때문에 접근 인물·구실·대응이 달라질 수 있어야 한다.
계획의 `personalizationBasis`에 사건과 인용 ID를 연결하고 별도 검증자가 의미를 검사한다.
관련 맥락 하나로 충분할 수 있다. 질문 횟수·도메인별 필수 항목·실명·특별한 사건을 강제하지 않는다.
가상 사기 연락이 실제로 왔어야 하는 것도 아니다.

## 설정과 시간

- `DISCOVERY_REASONING_EFFORT`: 대화 판단에만 적용. 기본은 공급자 기본 설정이며 현재 로컬은 지원 여부를 확인한 `none`.
- `DISCOVERY_TIMEOUT_SECONDS`: 대화 호출 대기 설정, 기본 5초. 2초를 강제해 정상 응답을 오류로 바꾸지는 않는다.
- `PIPELINE_REASONING_EFFORT`: 상세 계획·의미 검증·생성에 적용. 현재 로컬은 `low`.
- 대화의 OpenAI 연결은 60초 keep-alive로 재사용한다. 요청별 timeout과 재시도 없음 설정을 유지한다.
- BE·FE API의 외부 success/data 형식과 endpoint는 유지했다. BE/FE 코드는 수정하지 않았다.

2026-11-19 실제 평가: 같은 모델, 대화 4회 2.536 / 1.476 / 1.263 / 1.335초.
평균 1.652초, 2초 이내 3/4회다. 첫 요청을 포함해 항상 2초를 보장하는 결과는 아니다.
별도 시나리오 만들기는 1회 48.447초였다. 대화 시간 단축은 이 작업을 버튼 클릭 시점으로 옮긴 결과도 포함한다.
FE/Spring 통신 전체 시간이 아닌 AI 서비스 함수의 시간이다. 표본이 작으며 일반적인 성공률·지연 보장은 아니다.
평가 프로토콜은 `deferred-discovery-v1`, 결과는 Git 제외된 `evaluation-results/20261119T082013396256Z/`에 있다.
검증 모델도 같은 계열 모델이므로 의미 오류가 없다고 보장하지 않는다. 실제 사례의 정답과 사람의 검토를 함께 사용한다.
