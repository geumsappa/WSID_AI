# 상황 파악·시나리오 생성 품질 평가

대상: AI-01 상황 입력·추가 질문, AI-03 시나리오 생성. 긴급 대응·역할극·리포트 평가는 대상이 아닙니다.
실제 서비스 함수와 DTO를 호출합니다. HTTP 인증, Spring, FE 연결은 별도 통합 테스트 대상입니다.

## 실행

WSID_AI 폴더의 터미널에서 실행합니다. IntelliJ에서는 같은 모듈명을 Python 실행 구성의 Module name으로 설정할 수 있습니다.

```powershell
# 평가 사례 목록 (API 호출 없음)
.\.venv\Scripts\python.exe -m evaluations.discovery_scenario.runner --list

# 기본: 가짜 AI로 도구 작동 확인 (비용 없음, 실제 품질 점수 아님)
.\.venv\Scripts\python.exe -m evaluations.discovery_scenario.runner

# 실제 AI: 먼저 채용 사례 하나만 확인
.\.venv\Scripts\python.exe -m evaluations.discovery_scenario.runner --live --case job-bank

# 전체 14개 사례 × 3회: 실제 AI 호출 및 비용 발생
.\.venv\Scripts\python.exe -m evaluations.discovery_scenario.runner --live --repeats 3
```

작업 디렉터리는 WSID_AI입니다. 실제 실행은 기존 `.env`의 `LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY`를 사용합니다.
키를 명령어에 넣지 마세요. `--live`가 없으면 외부 LLM을 사용하지 않습니다.
14개 사례에는 22번 상황 파악과 9번 시나리오 생성이 있습니다(반복 1회 기준). 서비스 내부 재시도로 외부 호출 수가 더 늘 수 있습니다.

결과는 `evaluation-results/<UTC 실행 시각>/` 아래에 생성됩니다.

- `summary.md`: 성공 수/전체 수, 비율, 기능별 처리 시간 통계·실패율·기본 응답 대체율
- `results.json`: 입력, 턴별 사실·질문, 시나리오, 실패한 기준, 소요 시간
- `manual-review.csv`: Excel 등에서 열어 사람이 채점할 결과

결과 폴더는 Git에서 제외합니다. 제공 사례는 합성 데이터입니다. 실제 개인정보로 사례를 추가하지 마세요.
실제 평가에서 기능 기준에 실패하면 종료 코드 1을 반환합니다. mock은 도구 점검이므로 점수와 관계없이 종료 코드 0입니다.

## 자동 평가 기준

| 항목 | 통과 조건 | 집계 단위 |
| --- | --- | --- |
| fact_contains / fact_excludes | 추출된 사실에 필요한 표현이 있고 정정된 옛 표현·지어낸 기관명이 없음 | 기대 표현 1개 |
| fact_category / fact_type | 활동 분류와 공개 훈련 코드가 기대값과 동일 | 사례 실행 1회 |
| readiness | 모호한 답변은 준비 안 됨, 충분한 구체적 상황은 준비됨 | 준비 여부 기준이 있는 실행 |
| turn_readiness | 모호한 답변의 중간 턴에도 성급하게 준비 완료 처리하지 않음 | 지정된 입력 턴 |
| no_invented_request | 평범한 활동에 요구 행동·위험 요소를 임의 추가하지 않음 | 해당 실행 |
| no_exact_duplicate_facts | 공백·끝 문장부호 정리 후 동일한 사실 문장 없음 | 실행 1회 |
| followup_present / no_exact_repeated_question | 준비되지 않았다면 질문 존재, 질문이 정확히 반복되지 않음 | 최종 준비 안 됨 실행 |
| scenario_schema | 기존 Scenario Pydantic 모델 검증 통과 | 생성 실행 |
| scenario_type / scenario_channel | 기대하는 유형·연락 경로 유지 | 해당 생성 실행 |
| scenario_context | 화면에 보이는 제목·인물·배경·첫 대사에 기관명 반영 | 기대 표현 1개 |
| execution | 예외 없이 서비스 실행 완료 | 실행 1회 |

통과율 = 통과 항목 수 / 해당 항목 평가 수. 실행 예외 시 적용되는 미완료 항목도 실패로 셉니다.
검사 대상은 서비스의 검증·보정이 끝난 최종 출력입니다. 원본 LLM 응답의 정확도나 JSON 형식 오류율을 직접 측정하는 지표는 아닙니다.
동일 표현 비교는 의미 전체의 정확도를 증명하지 않습니다. 바꿔 쓴 동의어 때문에 실패할 수 있고, 의미가 같은 다른 문장을 중복으로 잡지 못합니다.
실패 결과를 읽고 기대 표현을 수정할지 실제 코드를 수정할지 결정하세요. 생성 결과에 맞춰 무조건 정답을 바꾸면 안 됩니다.

대체 응답은 `fallback_used`를 서비스 함수에서 관측하며 프로덕션 응답 형식을 바꾸지 않습니다.
질문 교체 같은 보정도 대체 응답에 포함될 수 있으므로 모두 외부 API 장애로 해석하지 마세요.
기능 통과 수와 대체 없이 통과한 수를 분리합니다. mock 점수는 실제 모델 평가에 사용하지 않습니다.
평균 실행 시간은 사례별 전체 처리 시간이며 입력 턴 수가 달라 순수 모델 응답 시간과는 다릅니다.

## 사람이 평가할 기준

`manual-review.csv`의 점수 칸은 미평가 상태로 비워 둡니다. 0은 실패이지 미평가가 아닙니다.

| 점수 | 자연스러움 | 개연성 | 사실과 가상 사건 구분 |
| --- | --- | --- | --- |
| 0 | 이해하기 어렵거나 대화가 모순됨 | 사용자 상황과 무관하거나 전개가 모순됨 | 실제로 사기 피해·연락이 있었다고 거짓 단정 |
| 1 | 이해되지만 반복·어색한 표현이 있음 | 관련은 있으나 연결이 억지스러움 | 구분이 모호해 사용자가 오해할 여지가 있음 |
| 2 | 자연스럽고 질문의 목적이 분명함 | 활동·연락 경로와 전개가 잘 연결됨 | 실제 입력과 훈련용 가정이 명확히 구분됨 |

시나리오가 없는 사례의 개연성·사실/가상 구분은 공란으로 둡니다. 수동 점수는 자동 통과율에 합치지 않습니다.
정정 결과에 옛 기관명 남음, 모호한 답변 강제 완료, 허구의 피해 단정은 우선 수정 대상입니다.
초기에는 임의의 합격률로 배포를 결정하지 말고, 첫 실제 평가를 기준선으로 삼아 동일 사례·모델·반복 수로 변경 전후를 비교하세요.
results.json에는 모델, 반복 수, 사례 파일과 프롬프트의 SHA-256을 남겨 평가 조건이 바뀌었는지 확인할 수 있습니다. API 키는 기록하지 않습니다.
점검용 작은 사례집이며 일반 사용자 전체에 대한 통계적 성능을 의미하지 않습니다.

## 평가 도구 자체 검증

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_discovery_evaluation.py -q
```

잘못된 정정·메타데이터만 복사한 시나리오·호출 예외·기본 응답이 성공률을 부풀리지 않는지 외부 호출 없이 검증합니다.


## 처리 시간 측정

상황 파악(discovery) 1회, 시나리오 생성(scenario) 1회를 각각 측정합니다.
서비스 호출부터 최종 결과 반환 또는 예외까지이며 재시도·검증·기본 응답 처리도 포함합니다.
외부 LLM API만의 시간이나 FE/Spring 통신 시간은 아닙니다. 기존 API 코드와 FE는 변경하지 않습니다.

summary.md와 results.json에 기능별 전체 / 기본 대체 없이 반환 / 기본 응답 대체 후 반환 / 예외로 실패의
호출 수와 평균·중앙값·P95(초)를 구분해서 표시합니다. 사례 전체 처리 시간도 따로 표시합니다.
빠른 기본 응답 때문에 실제 생성 속도가 빠른 것처럼 해석하지 않도록 결과를 나눕니다.
기본 대체 없이 반환된 결과도 기능 기준을 충족하지 않을 수 있습니다.

- 실패율 = 예외로 끝난 서비스 호출 수 / 해당 기능의 전체 시도 수
- 대체율 = 기본 응답을 사용하고 정상 반환한 서비스 호출 수 / 해당 기능의 전체 시도 수
- 기본 응답 사용 후 최종 처리에 예외가 나면 실패 그룹에만 포함합니다.
- 내부에서 처리된 타임아웃은 대체 응답으로 나타날 수 있어, 실패율을 외부 API 타임아웃 비율로 해석하면 안 됩니다.
- P95는 오름차순 ceil(0.95 × 표본 수)번째 값입니다. 표본이 적으면 통계적 참고값입니다.
- 호출이 없는 기능/결과 그룹의 시간과 비율은 미측정(null)으로 표시합니다. 0초/0%가 아닙니다.

각 호출의 status·예외 클래스·소요 시간은 results.json에 남깁니다. 예외 메시지나 키는 기록하지 않습니다.
API 호출 비용 없이 기본 명령으로 보고서 형식을 확인할 수 있지만 mock 시간은 실제 AI 성능이 아닙니다.
